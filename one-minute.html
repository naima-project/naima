Naima in one minute

Naima is a command-line program that lives in your project. Your AI agent calls it for each step of the work: filing a request, opening a branch, landing a change, recording a test run. The program does each step the same way every time, checks it, and writes it down as plain files in the repository. The agent decides what to do; Naima makes how it is done deterministic.

The commands your agent runs

naima hello
Starts every session: the version in use, the next goal and release, and anything waiting on you.
naima new
Turns a request, a bug or a decision into an item, after looking for duplicates.
naima open
Gives an item its own worktree and branch, and records who works on it.
naima land
Merges a finished branch into main as one commit naming the items it closes. A git hook refuses anything else on main.
naima run · wait
Runs a long job with a time budget and a progress record, and waits on the record instead of guessing.
naima verify
Checks a property of a model with the mCRL2 model checker and attaches the run as evidence.
naima gates
Says which goals and releases hold, and lists what each one still misses.
naima metrics
Measures size, complexity, duplication and coverage on each commit, and shows the trend.
naima pass
Writes the session note the next session starts from, so nothing stays only in a chat.
naima diary
Lists the project's decisions and turns, day by day, each with its reason.
naima decisions
Finds what was already settled, so you are not asked again.
naima announce
Writes the release notes from the work that was done and checked.

You only decide. The agent runs these for you; you are asked only what nobody else can settle, one question at a time.

The rules your agent works by

Quiet
As few AI tokens as the work allows: raw command output goes to a file, not into the context, and nothing written down is repeated in the chat.
Talking to you
The answer first, one question at a time, every number with what it is compared to.
Fast
Tests at the end of a phase, not after every edit; long jobs in the background while the conversation goes on.
Workers in the background
The agent you talk to hands each piece of work to a worker in its own worktree, and stays with you.
Ask first
Deleting data, rewriting history and any other step that can’t be reversed wait for your yes.
Nothing left hanging
What you settle is filed at once; each session ends with a note the next one starts from.

Yours to change. The rules ship with Naima and are listed by naima rules; a project can retire any of them or write its own.

It all lives in your project

One folder of your project holds it, versioned with git. The agent handles git for you.

If your code is public, that folder stays private: it becomes a git repository of its own, which your code’s repository ignores.

Change agent or model whenever you like: the work stays where it is.

your-project/ ├── your code, as before └── naima-tracker/ ├── naima/ # the program └── naima-data/ # requests, tests, # decisions, plans

Born for software, not only for it. It works for other long-lived work too, such as a data analysis or a paper written with colleagues.
