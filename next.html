What Naima does for your software

The practice of a serious software team, applied by your agents for you. You decide; Naima keeps everyone, people and agents, honest.

✓

Nothing lands untested

A change reaches your main line only with the test that shows it works, run and recorded.

◆

Decisions don't get lost

Every request, decision and requirement is written down in the project, so the next session starts where the last one ended.

↗

Goals you can see

Set a goal, reach it in steps, release it. Naima says what is missing, and writes the release notes from what was really done.

∀

The critical parts, proven

Behaviour with states or concurrency is designed as a model and checked with a model checker before it is coded.

≈

Quality over time

Size, complexity, duplication and coverage are measured on every commit, with budgets that hold the line.

⌂

Yours, in your repo

Plain files under one folder, versioned with your code. Works with any agent that can run a command.

Formal methods, working for you

The parts of your software that must never go wrong are designed as models and proven before they are coded. The agents write the models and the properties; you only say what must, and must not, happen.

  • State machines firstLifecycles, protocols, retries and user interface flows are designed as state machines before any code exists.
  • Model checkingThe mCRL2 model checker explores every order of events and shows the exact steps that break a property.
  • Properties in logic“A job is never retried more than twice” becomes a formula of the modal mu-calculus, checked again whenever the model changes.
  • MinimisationState spaces are reduced, keeping each property true, so large models stay checkable.
  • Code from the modelWith naima-codegen, a model becomes Rust, Python or TypeScript and Svelte state machines, checked against the model.

Born for software, not only for it. The same discipline runs a data analysis or a paper written with colleagues, with that work's own checks in place of tests.
