---
title: The window reads and acts through Naima's bridge commands, in the browser; its own server and native window are gone
kind: feature
affects:
  - usage
---

`naima ui` now serves the new interface in the default browser through the UI stance's bridge: everything the interface reads and does is one of Naima's bridge
commands (`describe`, `data`, `tabs`, `tab`, `metro`, `action`, `run`), answered at `POST /bridge/<command>` by the stance's request handler, and the project's
changes come on the bridge's feed `changes`, at `GET /bridge/changes`. The server's own routes (`/data/<view>`, `/data/tabs`, `/data/tab/<name>`, `/data/metro`,
`/events`, `/session`, `/action/<name>`, `/view/<name>` and the provisional window at `/classic`) are gone, and so is the native webview window with
`--browser`: `naima ui` opens the browser, and `--no-open` prints the address with its token, which also works through a port forwarded over ssh. A command is
refused from any page but the server's own. An action now starts its command as a run of `naima run`, which the `run` command shows. The views of `ui-views` no
longer have a first screen of panels: each is a tab of the interface. The guide page The Naima window (docs/guide/the-window.md) describes it.
