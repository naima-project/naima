# The basics

Naima can do a lot, but three things are enough to start with. You set a
goal, you reach it in steps, and you publish what you made. This page explains
each of them. Your agent does the work and keeps the records; you decide.

## Set a goal

A goal in Naima is called a gate. It has a name and a short description, such
as "the first public version" or "the paper ready for submission", and the
work that has to be finished before it is reached. Every piece of work that
matters for it, a feature to build or a bug to fix, is placed on the gate. The
gate holds when all of that work is done and checked, and not before.

You don't need to create gates yourself. Tell your agent what you want to
reach and by when, and it sets up the gate and puts the work on it. At the
start of every session it tells you the next goal and how far away it is.

## Reach it in steps

A large goal is easier to reach in smaller steps. Each step is a milestone, a
smaller gate with a date. When you ask how things stand, each milestone shows
how many days are left and what is still missing, item by item. When only one
or two things are left, Naima names them, so you know exactly what comes next.
A milestone that passes its date without holding is pointed out to you.

## Publish

A release is a gate with a version number, such as 1.0. When it holds,
everything it needed is done and checked, and what you publish follows from
it. The version is tagged in the project's history. The release notes are put
together from what the release did and proved (`naima announce`), and from
the short notes written with each change where the project keeps them, so
nobody has to remember afterwards what went in. Where the project has a website, it is
published too.

## Everything else

Behind these three steps there is more: tests that check every change, proofs
of the properties that matter most, several agents working side by side, and
models of how the system behaves. You don't need any of it to start. Ask your
agent about any of these when you are curious, and it will explain the part
you asked about.
