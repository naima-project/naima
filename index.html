For AI agents

Naima is born for software: a silent software house of AI agents that applies industry-grade practice (tests, metrics, reviews, gates) and formal methods for an owner who need not know them, and runs any other project with that work’s own checks. If you were asked to install Naima in a repository, the whole procedure is the README of https://github.com/naima-project/naima, section Install (raw: https://raw.githubusercontent.com/naima-project/naima/main/README.md; also llms.txt); read it and follow it. In short: if git is not installed, install it (macOS: xcode-select --install or Homebrew; Linux: the package manager; Windows: winget install Git.Git); then, in the root of this repository (if it is not a git repository yet, create one at the root with git init), run the installer one-liner for this system (install.html), run deno run -A naima-tracker/naima/naima.ts check until it passes, and commit what the installer wrote: naima-tracker/, and the line it added to the repository’s agent instruction file (AGENTS.md, CLAUDE.md, or the one you read; AGENTS.md, created, if none), which tells every agent to run naima hello at the start of each session. Then read naima-tracker/naima/skills/naima/SKILL.md and naima rules --audience agents, and work by them.

A project tracker built around the person who decides

Naima keeps your project's requests, decisions and goals in a folder of the project itself. AI agents do the work through it. They ask you only what needs a person. They show you the evidence before anything counts as done.

You stay in charge

Naima was designed for the owner of a project, the person who knows what the work is for. You do not need to know git, testing or formal methods. You need to say what you want and to decide when asked.

Asked only what is yours.

An agent asks you for a judgement, a decision, a password or something only you can do by hand. It asks one question at a time and suggests an answer. Your answer is written down and nobody asks it again.

Shown the proof.

Every test says who proves it. Most are settled by a command whose run is recorded. Some need an agent to use the running program and keep what it saw. A few are yours, and Naima waits for you.

Your words stay yours.

What you say to the agents is private. Nothing from your chat goes into the project without your yes.

What counts as proof

  1. You tried it and said yes.
  2. A screenshot, a log line or a number, with what it is compared to.
  3. The live state, read by a tool.
  4. A comparison before and after the change.
  5. “The code looks right.” This proves nothing on its own.

One place for the whole project

Naima is a tracker first. Requests, bugs, decisions and goals are kept as plain files in one folder of your repository. The agents read them at the start of every session. The work picks up where it stopped.

Goals and releases.

You set a goal and reach it in steps. Naima shows what is still missing and writes the release notes from what was done.

A diary of the project.

Each decision is kept with its reason. Months later you can still read why the project went one way.

Several agents at once.

Each piece of work gets its own branch. One coordinator brings them together, one at a time.

Any kind of project.

Naima was born for software. A data analysis or a paper written with colleagues works the same way, with its own checks in place of tests.

Naima keeps machine names, home paths and secrets out of the project. Any agent that can run a command can use it.

Formal methods, working for you

Some parts of a project must never go wrong. Think for instance of a payment that is retried, or a screen that waits for a server. Naima has these designed as small models and proven before any code is written. The agents write the models. You say what must happen and what must never happen.

  • State machines first.Behaviour with states is modelled in mCRL2 before it is coded.
  • Model checking.The mCRL2 model checker tries every order of events. When a property fails it shows the exact steps.
  • Properties in logic.“A job is never retried more than twice” becomes a formula of the modal mu-calculus. It is checked again whenever the model changes.
  • Code from the model.With naima-codegen the model becomes Rust, Python or TypeScript. A refinement check proves the code never takes a step the model forbids.
Naima checks itself.Its own coordination protocol is modelled in mCRL2 and checked with the model checker. See how →

You never touch git

You ask and you decide. The agents file the request, branch, test, merge and release. Naima checks each step.

  1. You ask“Keep a history of the results.”
  2. FiledThe request becomes an item in the project, triaged.
  3. BranchedAn agent opens a worktree and a branch of its own.
  4. TestedThe code comes with the test that shows it works, and the run is recorded.
  5. LandedMerged into main with a commit message that says what changed, and the item is closed.
  6. ReleasedWhen the goal holds: the tag and the release notes.
